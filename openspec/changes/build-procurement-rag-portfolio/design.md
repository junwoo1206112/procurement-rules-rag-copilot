## Context

현재 작업 폴더에는 채용공고 조사 문서만 있으며, 구현 기반은 새로 구성한다. 동기와 범위는 `proposal.md`를 따른다. 포트폴리오는 외부 API에 문서를 전송하지 않는 기본 경로와, 검색 품질을 수치로 설명할 수 있는 재현성을 모두 요구한다.

## Goals / Non-Goals

**Goals:**

- 국가법령정보센터의 조달 관련 법령·행정규칙 HTML 원문 30~50개를 대상으로 인용형 질의응답을 실행한다. PDF/HWPX는 파서 호환 형식으로 계속 지원한다.
- 검색 결과의 구조·출처·점수를 보존하고, 검색 실패가 답변 환각으로 이어지지 않게 한다.
- CPU 데모와 GPU 권장 환경을 분리해 Docker Compose로 재현한다.
- 동일 질의셋에서 검색 구성의 개선을 비교한다.

**Non-Goals:**

- 구형 HWP의 완전한 변환, 실시간 대규모 크롤링, 로그인·SSO·권한 관리, 입찰서 자동 작성은 구현하지 않는다.
- 법률·계약·입찰 결정을 대신하거나 최신 공고 여부를 보증하지 않는다.

## Decisions

### 문서 경계와 데이터 계보

문서 레코드는 원문 URL, 수집 시각, 발행 기관, 문서 유형, 이용 조건 확인 상태와 이용 가능 근거를 필수로 둔다. 1차 코퍼스는 저작권법 제7조의 보호 제외 범주에 해당하는 국가법령정보센터의 조달 법령·행정규칙으로 한정한다. 재학습이 아닌 검색 인덱싱으로 한정하고, 공개 접근 또는 이용 근거가 확인되지 않은 문서는 제외한다.

큐레이션 매니페스트는 단순 목록이 아니라, 허용 도메인에서 원문을 내려받아 본문 제목 일치·SHA-256·수집 시각을 확인한 뒤에만 색인한다. 수집 성공·실패와 해시는 응답으로 노출하며, 원문 파일 자체는 저장소에 커밋하지 않는다. URL을 클라이언트가 임의로 지정하는 수집 경로는 제공하지 않는다.

### 구조 보존 파싱과 청킹

PDF는 페이지·블록 단위, HWPX는 XML 구조 단위로 추출한다. 제목 계층을 따라 500~800 토큰, 80~120 토큰 겹침을 기본값으로 두되 조항과 표를 자르지 않는다. 고정 길이 청킹은 구현은 쉽지만 조항과 평가표의 의미를 잃을 수 있어 선택하지 않는다.

### Hybrid Retrieval + Reranking

Dense 검색은 의미가 비슷한 질의에, BM25는 공고번호·조항·날짜 같은 정확한 문자열에 강점이 있어 결합한다. 상위 20개 후보를 재정렬하고 최종 4~6개만 생성 문맥에 제공한다. 벡터 검색 단독은 단순하지만 키워드 정확도를 설명하기 어렵다.

### 로컬 우선 실행 경로

FastAPI, 검색 저장소, Ollama를 Docker Compose로 구성한다. 기본 답변은 로컬 Ollama 모델을 사용하고, 외부 모델 API는 비교 실험에서만 선택 가능하게 둔다. 이는 폐쇄망·민감 문서 적용 가능성을 보여주지만 CPU 성능 저하와 초기 모델 다운로드 비용을 수용한다.

### 근거 우선 답변 정책

검색 및 재정렬 점수가 임계값 미만이면 생성 대신 근거 부족을 반환한다. 답변 인용은 색인 청크와 원문 페이지가 일치하는지 검사한다. 모든 질문에 답하는 인상을 주기보다 검증 가능한 실패 처리가 채용 직무와 더 맞는다.

생성 모델은 `claim`과 `citation_ids`의 구조화된 결과만 반환하도록 요청한다. 각 claim은 하나 이상의 검색 청크 ID를 참조해야 하고, ID·문서 위치·최소 어휘 근거가 모두 검증되지 않으면 전체 생성 답변을 보류한다. 모델 장애 시에는 모델이 만든 문장이 아닌 검증된 원문 발췌만 데모 응답으로 반환한다.

## Risks / Trade-offs

- [PDF 표·스캔 품질 저하] → 파서·OCR 신뢰도를 청크 메타데이터에 노출하고, 낮은 신뢰도 문서는 평가에서 분리한다.
- [공개 문서의 이용 조건 변화] → 원문 URL, 수집 시각, 확인 결과를 보존하고, 검증되지 않은 문서는 제외한다.
- [로컬 모델의 느린 CPU 응답] → 경량 모델과 CPU 데모 모드를 제공하고 GPU 권장 사양을 문서화한다.
- [작은 평가 세트의 과도한 일반화] → 데이터셋 규모·한계·실패 사례를 리포트에 명시하고, 임의의 생산 성능을 주장하지 않는다.

## Migration Plan

1. 샘플 공개 문서와 평가 세트로 로컬 Compose 환경을 검증한다.
2. 색인·검색·인용 검증 API를 연결한 뒤, 웹 UI를 추가한다.
3. 세 가지 검색 구성을 같은 세트로 평가하고 리포트를 저장한다.
4. 릴리스 전 원문 링크, 문서 이용 조건, 비밀정보 제외 여부를 재검토한다.

롤백은 Compose 서비스를 중지하고 색인 저장소 볼륨을 제거하는 방식으로 수행하며, 원문 문서는 저장소에 커밋하지 않는다.
