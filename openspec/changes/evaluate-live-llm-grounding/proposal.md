## Why

현재 v4.0 평가는 검색 품질과 결정론적 근거·인용 계약을 검증하지만, 실제 Ollama가 생성한 문장이 근거를 정확히 요약하는지까지는 측정하지 않는다. 전문가 인터뷰 기록에서 확인한 것처럼 ‘인용이 있다’는 사실만으로 직접 근거를 사용했다는 보장이 되지 않으므로, 실제 생성 결과를 재현 가능한 별도 평가 대상으로 만들 필요가 있다.

## What Changes

- 고정 평가 세트의 답변 가능·불가 질의에 대해 실제 Ollama 생성 결과를 수집하고, 모델·프롬프트·실행 실패 여부를 함께 기록한다.
- 생성 문장별로 지원되는 핵심 주장, 인용 정확성, 보류의 적절성을 사람이 검토 가능한 형식으로 판정하고 집계한다.
- LLM 또는 인프라 준비 실패를 품질 실패와 구분하며, 실패 결과를 성공 지표에 섞지 않는다.
- 정답 근거와 다른 문서를 인용한 경우, 형식상 인용이 있더라도 불일치 사례로 보고한다.
- 기존 답변 안전 상태와 평가 리포트에 실제 모델 평가의 범위·비용·한계를 명시한다. 기존 API 응답 형식은 변경하지 않는다.

## Capabilities

### New Capabilities

- `live-llm-grounding-evaluation`: 실제 생성 결과, 근거 판정, 실행 실패를 재현 가능한 평가 산출물로 기록하고 보고하는 기능

### Modified Capabilities

- `quality-aware-rag-answering`: 실제 생성 답변이 선택 근거와 인용에 부합하지 않을 때 안전한 보류로 전환하는 요구사항을 확장
- `retrieval-quality-optimization`: 결정론적 근거 계약과 실제 LLM 생성 품질을 분리해 같은 고정 평가 세트에서 보고하는 요구사항을 확장

## Impact

- 영향 코드: `app/answering.py`, `app/evaluation.py`, `app/run_evaluation.py`, 평가 결과·리포트 생성 코드, 관련 테스트
- 영향 데이터: 평가 세트에 생성 검토 기준 또는 기대 판정 메타데이터를 추가하고, 모델 실행 결과는 별도 산출물로 저장
- 영향 운영: Docker/Ollama가 준비된 환경에서만 live 평가를 실행하며, 모델명·프롬프트 버전·코퍼스 해시·실행 시각을 기록
- 영향 문서: `README.md`, `docs/evaluation-report.md`, `docs/프로젝트_전문가_인터뷰_기록.md`에 측정 범위와 한계를 갱신
