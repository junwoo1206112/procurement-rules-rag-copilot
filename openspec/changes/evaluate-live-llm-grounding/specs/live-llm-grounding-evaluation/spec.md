## Purpose

실제 로컬 LLM이 생성한 답변을 선택 근거와 정답 근거에 비추어 검토 가능하게 남기고, 모델·인프라 실패와 생성 품질 문제를 분리해 신뢰 가능한 포트폴리오 평가 증거를 제공한다.

## ADDED Requirements

### Requirement: 실제 생성 실행 결과를 재현 가능한 단위로 기록한다
시스템은 실제 LLM 평가를 실행할 때 각 질의의 모델 식별자, 프롬프트 버전, 코퍼스 해시, 실행 시각, 답변 상태, 생성문, 인용과 실행 결과를 함께 기록해야 한다(MUST). 기록에는 비밀 키나 사용자 식별 정보가 포함되어서는 안 된다(MUST NOT).

#### Scenario: 답변 가능 질의의 실제 생성
- **WHEN** 모델과 코퍼스가 준비된 환경에서 답변 가능 질의를 평가한다
- **THEN** 시스템은 생성문·반환 인용·선택 근거 식별자와 평가 재현 메타데이터를 같은 실행 결과에 기록한다

#### Scenario: 모델 또는 인프라를 사용할 수 없다
- **WHEN** 모델 연결, 모델 준비 또는 요청 실행이 실패한다
- **THEN** 시스템은 실패 원인과 질의 식별자를 기록하고 해당 결과를 생성 품질 성공으로 집계하지 않는다

### Requirement: 실제 생성의 근거 적합성을 검토 가능한 형식으로 보고한다
시스템은 각 실제 생성 결과에 대해 핵심 주장 지원 여부, 인용이 정답 근거와 일치하는지, 답변 보류가 적절한지를 검토 가능한 항목으로 제공해야 한다(MUST). 형식상 인용이 있어도 정답 근거와 다른 문서를 인용하면 인용 적합으로 판정해서는 안 된다(MUST NOT).

#### Scenario: 직접 근거와 다른 문서를 인용한다
- **WHEN** 생성문에 인용이 있으나 그 인용이 고정 평가 세트의 정답 근거와 일치하지 않는다
- **THEN** 시스템은 해당 결과를 인용 불일치 사례로 기록하고 성공 인용 수에 포함하지 않는다

#### Scenario: 답변 불가 질의를 안전하게 보류한다
- **WHEN** 답변 불가 질의가 `insufficient_evidence` 상태와 빈 인용으로 반환된다
- **THEN** 시스템은 보류 적절 사례로 기록하고 모델 생성 품질의 정답 사례와 구분한다

### Requirement: 생성 품질 지표의 분모와 한계를 공개한다
시스템은 실제 LLM 평가 리포트에 평가 질의 수, 성공 실행 수, 인프라 실패 수, 검토 완료 수와 각 지표의 분모를 기록해야 한다(MUST). 결정론적 근거 계약 지표를 실제 생성문 품질로 표현해서는 안 된다(MUST NOT).

#### Scenario: 일부 질의에서 모델 실행이 실패한다
- **WHEN** 실제 LLM 평가 중 일부 질의가 인프라 또는 모델 오류로 완료되지 않는다
- **THEN** 시스템은 완료된 생성 결과의 품질 지표와 실패 건수를 분리해 보고한다
