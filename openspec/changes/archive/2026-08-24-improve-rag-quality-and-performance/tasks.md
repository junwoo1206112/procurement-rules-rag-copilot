## 1. 관련 근거 선택과 안전한 답변 경로

- [x] 1.1 검색 결과에서 문서명·조항·공고번호·본문 어휘 일치를 우선 계산하는 생성 전용 근거 선택기를 구현하고, 단일 질의는 직접 근거를 우선하며 비교 질의는 문서별 근거를 보존하는 단위 테스트로 검증한다.
- [x] 1.2 `OllamaAnswerer`가 선택된 근거만 모델 문맥과 claim 인용에 사용하도록 연결하고, 직접 조항 질의가 실제 문서명·섹션·원문 URL 인용의 `grounded` 응답을 만드는 통합 테스트로 검증한다.
- [x] 1.3 관련 근거가 없으면 모델 호출 없이 `insufficient_evidence`와 빈 인용을 반환하고, 모델 응답·claim 검증이 실패하면 미검증 문장 없이 `grounded_demo`와 검증된 발췌를 반환하는 회귀 테스트로 검증한다.
- [x] 1.4 상태별 제한된 내부 원인 코드와 구조화 로그를 추가하되 기존 API 상태·인용 응답 호환성을 유지하고, 세 상태와 인용 정합성 테스트가 모두 통과하는지 검증한다.

## 2. 평가와 성능 측정 확장

- [x] 2.1 고정 평가 실행이 선택 근거의 정답 중복 여부, `grounded`·`grounded_demo`·`insufficient_evidence` 상태별 건수·비율, 데이터셋 버전과 코퍼스 해시를 결과 JSON에 기록하도록 구현하고 평가 단위 테스트로 검증한다.
- [x] 2.2 사용자 요청과 같은 단건 검색 조건에서 `lexical_hybrid`, `embedding`, `hybrid`, `hybrid_rerank`의 Recall@5·MRR·nDCG·citation precision/recall·p50/p95를 비교하고, 낮은 구성의 실패 사례를 남기는 평가 테스트로 검증한다.
- [x] 2.3 모의 Ollama 응답을 사용한 결정론적 답변 상태 평가와 선택적 실제 Ollama E2E 실행 명령을 추가하고, 네트워크·모델이 없어도 전체 자동 테스트가 실행되는지 검증한다.

## 3. 결과 보고와 포트폴리오 증거 정합성

- [x] 3.1 `data/evaluation-results.json`에서 `docs/evaluation-report.md`를 재생성하는 경로를 구현하고, 질문 수·코퍼스 해시·구성별 지표·상태 비율·실패 사례가 결과 JSON과 일치하는 테스트로 검증한다.
- [x] 3.2 새 평가를 실행해 결과 JSON·평가 리포트·README의 기본 구성 판단과 수치를 함께 갱신하고, 기본값보다 낮은 구성은 개선으로 주장하지 않는지 교차 대조한다.
- [x] 3.3 전문가 인터뷰 기록에 품질 고도화의 A/B 교차검증, 실제 측정 조건, 미해결 한계를 반영하고, 템플릿의 품질·실패·재현성 축이 모두 근거 링크와 함께 채워졌는지 검토한다.
