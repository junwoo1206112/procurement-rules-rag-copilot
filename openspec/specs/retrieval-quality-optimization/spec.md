# retrieval-quality-optimization Specification

## Purpose

검색 구성과 생성 답변 상태를 같은 고정 데이터에서 재현 가능하게 측정해, 포트폴리오의 품질·성능 주장을 실제 비교 증거에만 근거하도록 한다.

## Requirements

### Requirement: 답변 상태별 품질을 고정 평가 세트에서 측정한다
시스템은 버전 관리되는 평가 세트에서 검색 품질과 함께 생성 답변·원문 발췌·근거 부족 상태의 건수와 비율을 산출해야 한다(MUST). 측정 결과에는 데이터셋과 코퍼스 버전이 포함되어야 한다(MUST).

#### Scenario: 구성별 평가를 실행한다
- **WHEN** 두 개 이상의 검색 또는 문맥 구성으로 고정 평가가 실행된다
- **THEN** 시스템은 각 구성의 Recall@k·MRR·nDCG·인용 precision/recall 및 답변 상태별 비율을 같은 리포트에 기록한다

### Requirement: 단건 성능과 개선 한계를 투명하게 보고한다
시스템은 사용자 요청과 같은 단건 검색 방식으로 p50/p95 지연시간을 측정해야 한다(MUST). 기본 구성보다 품질이 낮거나 지연시간이 높아진 구성은 개선으로 주장해서는 안 된다(MUST NOT).

#### Scenario: 후보 구성의 품질이 기준선보다 낮다
- **WHEN** 후보 구성의 고정 평가 지표가 기준선보다 낮다
- **THEN** 리포트는 해당 구성을 기본값으로 채택하지 않고 낮아진 지표와 실패 사례를 함께 기록한다
